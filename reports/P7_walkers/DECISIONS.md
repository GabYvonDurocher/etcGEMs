## D2 — the lock file drops the git-pinned editable line; etcgem is installed editable from the checkout

**Where:** TASK 0, the venv.

`pip freeze` of the old venv lists etcgem as `-e git+ssh://…@2af5815#egg=etcgem`: an editable
install recorded as a git URL at one commit. Reproducing THAT would clone the repository into the
venv, which is the opposite of what a lock file is for here. **Decided:** the lock keeps every
third-party pin (137 lines, numpy 2.0.2, scipy 1.13.1, cobra 0.31.1, gurobipy 12.0.3, emcee 3.1.6,
h5py 3.14.0, PyYAML 6.0.3) and replaces the etcgem line with a comment; etcgem is installed with
`pip install -e <checkout> --no-deps`, pointing at the primary tree. Consequence, written into the
README: the venv is shared, but the editable `etcgem` resolves to the primary checkout — a
worktree must run with `PYTHONPATH=<worktree>/src` (as K4–K9 did) or it silently imports the
primary tree's code. The interpreter is the same one the old venv wraps
(`/Library/Developer/CommandLineTools/…/3.9`, 3.9.6), so the move is a re-installation, not an
upgrade. The old venv is left in place.
