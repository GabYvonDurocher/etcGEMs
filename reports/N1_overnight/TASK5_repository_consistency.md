# TASK 5 — repository consistency

_N1 TASK 5. `outputs/tpc/` was committed for `eciML1515` and `_toy` and absent for the rest.
Either rule is defensible; the inconsistency is not. This picks one, applies it to all seven
strains, documents it in `README.md`, and lists what it did not fix._

## The rule

> **Every strain commits its nominal TPC.** Beyond that, an output directory is committed
> when a committed report, README or verification script reads it, and is scratch otherwise.

Applied:

| strain | directory | note |
|---|---|---|
| `_toy` | `outputs/tpc/` | already committed |
| `eciML1515` | `outputs/tpc/` | already committed — **and stale**, see below |
| `mmaripaludis` | `outputs/tpc/` | committed |
| `syn6803` | `outputs/tpc_syn6803_ecmodel/` | needs an overlay; see below |
| `cauris_iRV973` | `outputs/tpc/` | committed |
| `chaemulonii_draft` | `outputs/tpc/` | committed |
| `cduobushaemulonii_draft` | `outputs/tpc/` | committed |
| `cparapsilosis_iDC1003` | `outputs/tpc/` | committed |

**Why this rule and not the other.** The alternative — treat the nominal TPC as scratch and
gitignore it everywhere — is cleaner in one way: nothing committed can go stale. But applying
it would mean removing `eciML1515`'s and `_toy`'s committed copies, and the standing rules for
this night forbid deleting committed evidence outright. The chosen rule adds files and deletes
none. It also has a property the other lacks: a committed nominal TPC that stops reproducing
is a *signal*. `eciML1515`'s already is one.

**`syn6803` needed one change to be included.** Its `strain.yaml` carries `provider.type: fba`
as a P1 placeholder, so `etcgem tpc --strain syn6803` cannot build its real model. `etcgem tpc`
now takes an optional `--experiment`, exactly as `etcgem fba` already did, so the K2 overlay
`configs/experiments/syn6803_ecmodel.yaml` builds the enzyme-constrained model through the
shared command: `etcgem tpc --strain syn6803 --experiment syn6803_ecmodel` →
`outputs/tpc_syn6803_ecmodel/` (Topt 41.0 °C, rmax 0.070 /h, CTmax 50.0 °C). With no
`--experiment` the command is byte-for-byte what it was: verified on `eciML1515` and
`mmaripaludis`, all three files each.

## `gate_table.csv`

**Tracked, deliberately.** It is the machine-readable form of K1's gate table, it is cited by
`reports/candida_thermal_limit/K1_port_verification.md`, and it is regenerated by
`gate_table.py` (which since TASK 2 needs no external repository). It meets the rule's second
clause — a committed report reads it — so it stays.

## Other inconsistencies found

Listed rather than fixed. Each would change or remove a committed artefact of a strain other
than the Candida four, which the standing rules put outside this night's remit.

1. **`strains/eciML1515/outputs/tpc/` does not reproduce.** The committed file says
   Topt 37.0 °C, rmax 0.341; the current code produces Topt 31.0 °C, rmax 0.543. This predates
   the whole Candida merge and is already recorded at the end of
   `reports/candida_thermal_limit/K1_port_verification.md`. Under the rule just adopted it is
   a signal that something changed and was not re-baselined. **Someone should decide whether
   to regenerate it or to find out what moved.** (`DECISIONS.md` D1.)

2. **Six `*_quick` / `*_v2` output directories are committed** under `strains/eciML1515/outputs/`
   — `sweep_quick`, `sweep_calibrated_quick`, `control_control_quick`,
   `decompose_decomposition_quick`, `calibration_vanderlinden_v2`,
   `calibration_vanderlinden_v3` — 47 tracked files between them. Their names say scratch; the
   `_v3` one in particular is superseded by `calibration_vanderlinden`. They are committed
   evidence and were not touched, but they do not meet the rule's second clause and are the
   obvious next tidy-up.

3. **Sixteen Python files live in strain folders**, against the project's own rule that a
   strain folder contains no code that implements the method (stated in
   `docs/CANDIDA_ETCGEM_PLAN.md` §2 and in `README.md`): two under `eciML1515`, six under
   `mmaripaludis`, eight under `syn6803`. `syn6803/run_p2_thermal.py` is the load-bearing one —
   it is the only way that strain's real model gets built, which is why TASK 2's and TASK 5's
   work needed the `syn6803_ecmodel` overlay to reach it at all. Moving them is a real piece of
   work with real risk to committed results, and belongs in its own prompt.

4. **`strains/mmaripaludis/outputs/tpc/` records an all-zero TPC.** That is correct — it is the
   maintenance-crushed a-priori state its own `strain.yaml` documents (`nominal_kcat_scale:
   7.223` is the calibrated operating point) — but a committed artefact of zeros invites
   misreading. The `sector_flatness.json` beside it now says why the descriptors are NaN.
